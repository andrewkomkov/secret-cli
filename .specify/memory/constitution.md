# secret-cli Constitution

Правила для любой работы с командой `secret`. Каждая фича в `specs/` проверяется по этому
документу до первой строки кода.

## Core Principles

### I. Значение секрета не выходит наружу
Значение печатается в stdout только командами, которые для этого сделаны (`get`, `copy`
кладёт в буфер обмена). Значение не передаётся в аргументах процесса (`argv` видно в `ps`):
в `security` оно идёт через stdin `security -i`, в helper — через stdin или pipe. Журналы,
сообщения об ошибках, тесты и документы содержат имена секретов, а не значения. Новая команда,
которая выводит значение, — отступление, оно записывается в `plan.md` фичи. `secret gh` отдаёт
значение только в stdin `gh secret set`.

### II. Ввод и доступ подтверждает человек
Новое значение человек вводит в скрытое поле (терминал или окно macOS), не в чат агента.
Разблокировку keychain и подтверждение Touch ID делает человек. Пароль keychain команда не
хранит. Обойти эти шаги команда не даёт. Режим `SECRET_NO_DIALOG=1` завершает команду с
ошибкой там, где нужен человек.

Каждую отправку значения во внешнюю службу (`secret gh`) человек подтверждает в окне macOS.
Окно называет секрет, имя в GitHub и флаги `gh`. Без окна команда завершается с ошибкой.

В хранилище Secure Enclave каждое значение зашифровано открытым ключом из Secure Enclave. Его
закрытый ключ работает только после `.userPresence`: Touch ID, Apple Watch или пароль Mac.
Запись идёт без Touch ID, чтение требует Touch ID. Обёртку ключа Secure Enclave и ключ файла
хранит запись файлового keychain. Без вопроса её читает только helper.

Время без нового вопроса (grace) держит процесс-агент helper. После Touch ID агент читает
значения и держит их в своей памяти до конца grace. Hardened runtime без `get-task-allow`
закрывает эту память от отладчика. Grace скользящий: новый вопрос Touch ID нужен после N секунд без запросов. N — 3600
или меньше. Общий предел — 8 часов от Touch ID. Блокировка экрана, сон Mac и `secret lock`
заканчивают grace сразу. Файл-метка не заменяет подтверждение системы.

### III. Только то, что есть в macOS
Команда работает на `bash` 3.2 и системных утилитах macOS (`security`, `osascript`, `perl`,
`xxd`, `pbcopy`). Пакеты Homebrew, Python-библиотеки и сеть не нужны. Исключение — `secret gh`:
ей нужны `gh` и сеть. Компилируемый helper
допустим, только если его исходник лежит в репе и собирается `swiftc` из Command Line Tools.
Если helper не собран, команда работает без возможностей helper.

Helper хранилища Secure Enclave собирает `swiftc` из Command Line Tools. У этого helper нет
profile, entitlements и срока. Подпись — сертификат Apple Development владельца, иначе ad-hoc.
Hardened runtime включён. Платный аккаунт разработчика и provisioning profile — запрещённые
требования.

Приложение в строке меню SecretBar тоже собирает Xcode. Его подпись — сертификат Apple
Development владельца, без сертификата — ad-hoc. Hardened runtime включён, entitlements и
profile ему не нужны. Приложение вызывает только `bin/secret` и helper хранилища. Само
к keychain оно не обращается, значения в свою память не читает. Без приложения команда
работает так же.

### IV. Тест на временном хранилище
Каждая фича добавляет проверки в `tests/run.sh`. Тесты создают свой keychain и удаляют его,
рабочий keychain `secrets` и список Keychain Access не меняются. Тесты не открывают окна:
то, что требует человека (окно, Touch ID), проверяется руками и записывается в `tasks.md`
как ручная проверка с датой.

Тестовая сборка helper хранилища Secure Enclave держит программный ключ и ключ файла в каталоге
прогона. Secure Enclave и keychain она не трогает. Тестовый Touch ID — ответ из файла.

### V. Совместимость
Существующие команды, формат ссылок `secret:NAME`, account `secret-cli` и путь keychain по
умолчанию не меняются. Новая возможность — это новая команда или новый флаг. Если меняется
поведение команды, которая уже есть, это отступление с причиной в `plan.md`.

Хранилище Secure Enclave включает `secret migrate --backup FILE`, обратно в файловый keychain —
`secret migrate --back`. Переезд проверяет каждое значение в новом хранилище и только потом
переключает команду. Пока хранилище Secure Enclave не включено, команда работает с файловым
keychain, как раньше.

## Технические ограничения

- Keychain: `~/Library/Keychains/secrets.keychain-db`, другой — через `SECRET_KEYCHAIN`.
- Запись: generic password, account `secret-cli`, service — имя, kind `secret-cli`,
  комментарий — атрибут `icmt`.
- Хранилище Secure Enclave: файл `~/.local/share/secret/vault`. Весь файл зашифрован AES-GCM
  ключом файла: имена скрыты, подмену файла helper замечает. Каждое значение внутри ещё
  зашифровано ECIES (P-256, HKDF-SHA256, AES-GCM) открытым ключом Secure Enclave. Ключ файла и
  обёртка ключа Secure Enclave лежат в записи файлового keychain входа: generic password,
  service `secret-cli.vault`, account `secret-cli`. Новый ключ helper создаёт только для пустого
  хранилища. Если файл есть, а записи нет, helper завершается с ошибкой. `ls`, `has`, `check`,
  `note`, `expire` открывают файл ключом файла, без Touch ID.
- Имена: `^[A-Za-z_][A-Za-z0-9_.-]*$`. Значения однострочные.
- Команда — один файл `bin/secret`, ставится symlink-ом через `install.sh`.

## Порядок работы

- Любое изменение идёт через spec-kit: `specs/NNN-slug/` со `spec.md`, `plan.md`, `tasks.md`.
- Галочка в `tasks.md` ставится на проверенный факт: код есть, тест прошёл.
- `tests/run.sh` проходит целиком перед каждым коммитом.
- Коммиты — Conventional Commits. Remote — публичная репа `github.com/andrewkomkov/secret-cli`. В файлах и
  коммитах нет данных владельца: имён его секретов, проектов, хостов, личных путей.
- Правила для агента лежат в `docs/claude-md-secrets.md` и совпадают с разделом Secrets в
  `~/.claude/CLAUDE.md`.

## Governance

Конституция выше устных договорённостей. Отступление записывается в `plan.md` фичи в разделе
«Complexity Tracking» с причиной. Изменение конституции — отдельный коммит с новой версией.

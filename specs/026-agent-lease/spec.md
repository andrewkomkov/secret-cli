# Feature Specification: Аренда секретов для агентов

**Feature Branch**: `026-agent-lease`. Работа идёт в `main` локальной репы.

**Created**: 2026-11-03

**Status**: Draft

**Input**: Блокировка экрана сразу заканчивает grace (принцип II). На заблокированном Mac Touch ID
спросить нельзя. Поэтому агент, который работает в отсутствие владельца, остаётся без секретов. Владелец
выбрал аренду (2026-11-03): явный набор секретов на срок до 24 часов. Аренда переживает
блокировку экрана и сон Mac. Агент может сам запросить аренду, Touch ID даёт владелец.

## User Scenarios & Testing *(mandatory)*

<!-- утр-100: 8.2 — заголовок задан шаблоном spec-kit -->
### User Story 1 - Агент работает при заблокированном экране (Priority: P1)

Владелец уходит от Mac. Перед этим агент запрашивает аренду нужных секретов, владелец
подтверждает Touch ID. Владелец блокирует экран. Агент продолжает работу и получает эти
секреты.

**Why this priority**: это цель фичи.

**Independent Test**: тестовая сборка. `secret lease SHOP_DB_PASSWORD`, тестовый Touch ID «да».
Сигнал блокировки экрана. `secret run --mask SHOP_DB_PASSWORD -- cmd` работает без вопроса
Touch ID.

**Acceptance Scenarios**:

1. **Given** аренда `SHOP_DB_PASSWORD`, **When** экран заблокирован и `secret run` читает
   `SHOP_DB_PASSWORD`, **Then** команда получает значение без вопроса Touch ID.
2. **Given** аренда `SHOP_DB_PASSWORD`, **When** Mac был во сне и проснулся, **Then** аренда
   действует.
3. **Given** аренда только `SHOP_DB_PASSWORD`, **When** экран заблокирован и `secret run`
   читает `BILLING_API_KEY`, **Then** команда сразу даёт ошибку
   `not leased: BILLING_API_KEY`. Команда не открывает окно и сразу выходит.
4. **Given** аренда и открытый экран, **When** `secret run` читает секрет из аренды,
   **Then** команда получает значение без Touch ID. Для секрета вне аренды действуют правила
   grace из фичи 010.

<!-- утр-100: 8.2 — заголовок задан шаблоном spec-kit -->
### User Story 2 - Запрос аренды и подтверждение (Priority: P1)

**Why this priority**: без подтверждения владельца аренды нет.

**Independent Test**: тестовая сборка, ответ Touch ID из файла. «Да» даёт аренду, «нет» —
ошибку без аренды.

**Acceptance Scenarios**:

1. **When** `secret lease --for 6h SHOP_DB_PASSWORD SHOP_API_KEY`, **Then** окно Touch ID
   называет оба имени и срок. После «да» команда показывает имена и время конца аренды.
2. **When** `secret lease -e .env`, **Then** в аренду идут все имена из ссылок `secret:NAME`
   этого файла.
3. **When** агент запускает `secret lease`, **Then** окно Touch ID открывается так же. Хук не
   останавливает эту команду.
4. **When** владелец отвечает «нет» или закрывает окно, **Then** команда даёт ошибку и
   аренды нет.
5. **When** grace активен, **Then** `secret lease` всё равно спрашивает новый Touch ID.
6. **When** экран заблокирован, **Then** `secret lease` сразу даёт ошибку: на заблокированном
   экране Touch ID спросить нельзя.
7. **When** `--for` больше 24 часов или имя не найдено, **Then** ошибка, аренды нет.

<!-- утр-100: 8.2 — заголовок задан шаблоном spec-kit -->
### User Story 3 - Конец аренды (Priority: P1)

**Why this priority**: аренда длится долго. Владелец должен знать её срок и закрыть её сам.

**Independent Test**: тестовая сборка, предел аренды из переменной окружения.

**Acceptance Scenarios**:

1. **Given** аренда на N часов, **When** N часов прошло, **Then** чтение даёт
   `not leased: NAME`. Запросы срок не продлевают. Время сна Mac входит в срок.
2. **When** `secret lease --revoke`, **Then** команда сразу заканчивает все аренды.
3. **When** `secret lock`, **Then** команда заканчивает grace и все аренды.
4. **When** перезагрузка Mac или выход владельца из системы, **Then** аренды нет.
5. **When** `secret set` или `secret ask` меняет секрет из аренды, **Then** этот секрет выходит
   из аренды. Старое значение команда больше не отдаёт.

<!-- утр-100: 8.2 — заголовок задан шаблоном spec-kit -->
### User Story 4 - Статус, журнал и SecretBar (Priority: P2)

**Acceptance Scenarios**:

1. **When** `secret lease status`, **Then** команда показывает имена в аренде и время конца
   каждого. Значений нет, Touch ID не нужен.
2. **When** `secret log`, **Then** чтение из аренды помечено как `lease`.
3. **Given** аренда, **Then** SecretBar показывает, что аренда есть, сколько в ней имён и когда
   срок аренды закончит. Кнопка в SecretBar отзывает все аренды.

### Edge Cases

- Две аренды подряд: имена добавляются. У каждого имени свой конец. Если имя уже в аренде,
  остаётся более поздний конец.
- `secret lease` с `SECRET_NO_DIALOG=1`: ошибка, аренды нет.
- Хранилище — файловый keychain (до `secret migrate`): `secret lease` завершается с ошибкой
  `lease needs the secure enclave store`.
- Процесс helper, который держит аренду, упал: аренды нет, следующий запрос идёт по обычным
  правилам.
- Часы Mac перевели: срок аренды считается по монотонным часам, которые включают сон.
- Секрет удалили (`secret rm`) во время аренды: он выходит из аренды.
- Пустой набор имён (например, `.env` без ссылок): команда даёт ошибку до окна Touch ID.

## Requirements *(mandatory)*

<!-- утр-100: 1.9 — идентификаторы требований заданы шаблоном spec-kit -->
### Functional Requirements

- **FR-001**: Новая команда `secret lease [--for DURATION] NAME... | -e FILE`. DURATION —
  число с `m` или `h`. По умолчанию 8 часов. Больше 24 часов — ошибка.
- **FR-002**: Каждая аренда требует новый Touch ID. Grace его не заменяет. Текст окна называет
  имена и срок.
- **FR-003**: Аренда держит значения только названных секретов. После блокировки экрана
  helper отдаёт только эти значения.
- **FR-004**: Блокировка экрана и сон Mac заканчивают grace, как раньше, и не заканчивают
  аренду.
- **FR-005**: Срок аренды — от Touch ID. Запросы срок не продлевают.
- **FR-006**: Аренду заканчивают: конец срока, `secret lease --revoke`, `secret lock`,
  перезагрузка, выход из системы, изменение или удаление секрета (только для этого имени).
- **FR-007**: Если экран заблокирован и имени нет в аренде, команда сразу даёт ошибку
  `not leased: NAME`. Ошибка называет все такие имена. Команда выходит без окна.
- **FR-008**: `secret lease status` показывает только имена и время конца. Команда работает
  без Touch ID.
- **FR-009**: `secret log` пишет для чтения из аренды пометку `lease`. Запрос аренды и отзыв
  тоже идут в журнал.
- **FR-010**: Хук PreToolUse пропускает `secret lease`, `secret lease status` и
  `secret lease --revoke`.
- **FR-011**: SecretBar показывает активную аренду и отзывает её. Новые строки интерфейса
  получают перевод `ru` в той же правке.
- **FR-012**: `docs/claude-md-secrets.md` говорит агенту: перед долгой работой в отсутствие
  владельца запроси аренду нужных имён. При ошибке `not leased` остановись и сообщи владельцу.
- **FR-013**: Тестовая сборка: предел аренды и сигнал блокировки — из окружения и команды
  тестовой сборки. В рабочей сборке этого кода нет.
- **FR-014**: Конституция (принцип II) получает правило аренды: явный набор, Touch ID на
  каждую аренду, срок до 24 часов. Блокировка и сон аренду оставляют. Это отдельный коммит с
  новой версией конституции.

### Key Entities

- **Аренда**: имя секрета, значение в памяти helper, время Touch ID, время конца.
- **Grace**: как в фиче 010, без изменений.

## Success Criteria *(mandatory)*

<!-- утр-100: 1.9 — идентификаторы критериев заданы шаблоном spec-kit -->
- **SC-001**: Тест: после сигнала блокировки секрет из аренды читается, секрет вне аренды даёт
  `not leased` меньше чем за 1 секунду.
- **SC-002**: Тест: конец срока заканчивает аренду при непрерывных запросах.
- **SC-003**: Тест: `--revoke` и `lock` заканчивают аренду. `set` убирает имя из аренды.
- **SC-004**: Тест: `--for 25h` даёт ошибку. Ответ Touch ID «нет» не даёт аренды.
- **SC-005**: Ручная проверка: агент запросил аренду, владелец дал Touch ID и заблокировал экран
  на 30 минут. Агент получил секрет из аренды и ошибку для другого секрета.
- **SC-006**: Ручная проверка: аренда работает после сна Mac.

## Assumptions

- Во время аренды helper отдаёт арендованные значения любому процессу владельца, как в grace
  (фичи 009, 010). Аренда удлиняет это время, но только для явного списка имён.
- На заблокированном Mac человек у клавиатуры не может запустить команду. Поэтому аренда при
  блокировке экрана безопасна.
- Владелец видит в окне Touch ID имена и срок и сам решает, давать ли аренду.
- Агент держит Mac проснувшимся сам, если работа идёт ночью. Аренда это не делает.
- Аренда работает только в хранилище Secure Enclave. Файловый keychain остаётся как раньше.

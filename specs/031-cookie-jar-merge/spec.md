# Feature Specification: cookie import сливает jar, а не перезаписывает

**Feature Branch**: `031-cookie-jar-merge`. Работа идёт в `main`.

**Created**: 2026-11-04

**Status**: Draft 2026-11-04

**Input**: Владелец: «RSGE_SESSION теперь хранит только cookie decl.rs.ge — при сохранении
расширение заменило в нём cookie eservices. Хочется, чтобы расширение всё хранило и ничего не
перетирало».

## Цель

Захват с нового домена в тот же секрет **добавляет** его cookie и обновляет свои, но cookie других
доменов сохраняет. Один секрет собирает сессии нескольких сайтов.

## Контекст и границы

- `secret cookie import --as NAME` сейчас перезаписывает секрет целиком. Это и есть причина потери.
- Мёрж идёт по ключу `(домен, путь, имя)`. Cookie с тем же ключом берётся из нового jar (свежий),
  cookie других ключей из старого секрета сохраняются.
- Мёрж читает старый секрет, поэтому `import` в этом случае просит Touch ID (как любое чтение).
- Меняется только `cookie import`. Прочие команды и формат jar не меняются.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - мёрж по умолчанию (Priority: P1)

1. **When** человек выполняет `secret cookie import --as NAME` для существующего секрета, **Then**
   команда сливает новый jar со старым по ключу `(домен, путь, имя)`. Cookie других доменов
   остаются.
2. **When** в новом jar есть cookie с тем же ключом, **Then** побеждает новый (свежее значение и
   срок).
3. **When** секрета ещё нет, **Then** команда просто сохраняет новый jar, как раньше.
4. Комментарий и `-x` пересчитываются по итоговому набору: `N cookies`, список session-only,
   `-x` — самый ранний срок среди постоянных cookie.

### User Story 2 - полная перезапись по флагу (Priority: P2)

1. **When** человек выполняет `secret cookie import --as NAME --replace`, **Then** команда
   перезаписывает секрет новым jar целиком, старые cookie не читаются и Touch ID не нужен.

## Requirements *(mandatory)*

- **FR-001**: `cookie import` по умолчанию сливает новый jar с существующим секретом по ключу
  `(домен, путь, имя)`. Новый ключ побеждает, прочие cookie сохраняются.
- **FR-002**: `--replace` сохраняет поведение «перезаписать целиком» без чтения старого секрета.
- **FR-003**: при отсутствии секрета мёрж не нужен, команда сохраняет новый jar.
- **FR-004**: после мёржа команда пересчитывает комментарий и `-x` по итоговому набору.
- **FR-005**: значения cookie не идут в stdout, argv и лог. Мёрж идёт в памяти команды, итог — в
  хранилище.
- **FR-006**: демон и расширение не меняются: они зовут `cookie import` как раньше, мёрж получают
  по умолчанию.

## Success Criteria *(mandatory)*

- **SC-001**: захват eservices.rs.ge, затем decl.rs.ge в один секрет даёт jar с cookie **обоих**
  доменов.
- **SC-002**: повторный захват того же домена обновляет его cookie и не плодит дубликаты.
- **SC-003**: `--replace` перезаписывает секрет и не читает старый (без Touch ID).
- **SC-004**: значения cookie остаются вне stdout, argv и лога.

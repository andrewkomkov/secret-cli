# Research: записи, которые читает только helper

Прототип 2026-10-02 на временном keychain (`specs/007-protected-items/spike/spike.swift`), UI выключен
`SecKeychainSetUserInteractionAllowed(false)`, системных окон нет.

| # | Проверка | Результат |
|---|---|---|
| R1 | ACL записи, которую создал helper через `SecKeychainAddGenericPassword` | `decrypt` — только helper, требование `cdhash H"…"` (ad-hoc). `change_acl` — никто без пароля. `encrypt` — все |
| R2 | `SecKeychainItemSetAccess` после создания | `-128`: нужен UI. Не нужен: создатель и так единственный доверенный |
| R3 | Чтение после пересборки ad-hoc | доступа нет: `cdhash` другой |
| R4 | Подпись самоподписанным сертификатом | требование `identifier and certificate leaf`, пересборку переживает. Не берём: ключ подписи пришлось бы хранить, и им можно подписать чужой бинарник |
| R5 | Чтение бинарником с другой подписью | `-25293`, окна нет (UI выключен) |
| R6 | Изменение комментария бинарником с другой подписью | разрешено (`0`) |
| R7 | Удаление бинарником с другой подписью | разрешено (`0`) |
| R8 | Атрибуты через `security find-generic-password` без `-w` | читаются без окна |
| R9 | `codesign -o runtime` | флаг `runtime`: переменные `DYLD_*` не действуют, отладчик без `get-task-allow` не подключается |

Вывод: защищено только значение. Пересборка helper требует переноса записей старым helper в
новый (R3). Атрибуты и удаление не защищены (R6, R7).

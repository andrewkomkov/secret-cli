# Feature Specification: Хранилище data protection keychain

**Feature Branch**: `009-data-protection-store`. Работа идёт в `main` локальной репы.

**Created**: 2026-10-07

**Status**: Complete — 2026-10-07, рабочие секреты перенесены (T025)

<!-- утр-100: 8.7 — номер версии macOS -->
**Input**: Helper и команда работают на файловом keychain через API `SecKeychain*`. В macOS
10.10 Apple объявила этот API устаревшим. `swiftc` выдаёт 26 предупреждений. Владелец хочет
перейти на актуальное хранилище — data protection keychain. Платного аккаунта разработчика нет
и не будет. Проба 2026-10-07 показала, что бесплатная Personal Team в Xcode даёт доступ к этому
хранилищу (research R1–R8).

## User Scenarios & Testing *(mandatory)*

<!-- утр-100: 8.2 — заголовок задан шаблоном spec-kit -->
### User Story 1 - Секреты в новом хранилище (Priority: P1)

Владелец переносит все секреты в data protection keychain и дальше работает теми же командами.

**Why this priority**: это цель фичи: уйти с устаревшего API.

**Independent Test**: на тестовой сборке helper: `migrate` переносит записи, потом `get`, `run`,
`ls -l`, `check` дают те же результаты, что и до переноса.

**Acceptance Scenarios**:

1. **Given** собран helper хранилища и есть файловый keychain с записями, **When**
   `secret migrate --backup FILE`, **Then** команда сначала делает зашифрованную копию в `FILE`.
   Это копия того же вида, что делает `export`. Потом команда копирует все записи с
   комментариями и сроками в новое хранилище. Затем команда сверяет значения и включает новое
   хранилище.
2. **Given** новое хранилище включено, **When** любая команда, **Then** она работает с новым
   хранилищем. Это команды `set`, `get`, `run`, `ls`, `check`, `import`, `export`, `restore`,
   `mv`, `rm`, `note`, `expire`, `gen`, `ask`, `copy`. Ссылки `secret:NAME` в `.env` работают
   как раньше.
3. **Given** перенос не прошёл из-за отказа Touch ID или ошибки записи, **Then** новое
   хранилище выключено. Команда не меняет файловый keychain.
4. **Given** сверка прошла, **Then** `migrate` удаляет перенесённые записи из файлового keychain.
   Копия в `FILE` зашифрована. Старые записи в файловом keychain не имеют новой защиты. Если
   кто-то удалит файл режима, команда начнёт работать с этими записями.
   Файл keychain команда не удаляет, его удаляет владелец.

### User Story 2 - Чтение значения только после Touch ID (Priority: P1)

**Why this priority**: подпись Personal Team не защищает значение. Profile разрешает все access
groups команды, а подписать бинарник может любой процесс пользователя (research R4).

**Independent Test**: ручная проверка. Процесс с той же подписью получает значение только
после Touch ID.

**Acceptance Scenarios**:

1. **When** любой процесс читает значение из нового хранилища, **Then** система требует Touch ID
   или пароль Mac. Если человека нет, система возвращает ошибку. При `SECRET_NO_DIALOG=1` окно
   не открывается.
2. **When** `get`, `copy`, `run`, `export`, `mv`, `note`, `expire`, **Then** одна команда
   вызывает не больше одного вопроса Touch ID. Это предел для всех записей команды.
3. **When** `ls`, `ls -l`, `ls --expiring`, `has`, `check`, **Then** Touch ID не нужен. Команда
   читает имена, комментарии и сроки без Touch ID.
4. **When** `set`, `gen`, `import`, `restore`, `rm`, **Then** Touch ID не нужен. Команда пишет
   новое значение и удаляет запись, но старое значение она не читает.

### User Story 3 - Время без нового вопроса (Priority: P2)

**Why this priority**: агент вызывает `secret run` много раз подряд. Вопрос на каждый вызов
мешает работе.

**Independent Test**: на тестовой сборке два `get` подряд с grace 300 дают один ответ Touch ID.
После `secret lock` — снова вопрос.

**Acceptance Scenarios**:

1. **Given** grace N секунд, по умолчанию 300, **When** Touch ID подтверждён, **Then** следующие
   команды читают значения без вопроса. Это действует в течение N секунд.
2. **When** `secret lock`, **Then** команда сразу завершает grace.
3. **Given** grace 0, **Then** каждая команда спрашивает Touch ID.
4. **When** `secret touchid grace N`, **Then** нужен свежий Touch ID. N больше 3600 — ошибка.
5. **When** `secret touchid status`, **Then** видно хранилище, grace и срок profile.

### User Story 4 - Продление profile (Priority: P1)

**Why this priority**: profile бесплатной команды живёт 7 дней. Без продления helper перестаёт
запускаться, и секреты недоступны до пересборки.

**Independent Test**: `install.sh --renew` с датой profile ближе 3 дней пересобирает helper.
Если до даты больше 3 дней, команда ничего не делает.

**Acceptance Scenarios**:

1. **Given** до конца срока profile меньше 3 дней, **When** `install.sh --renew`, **Then**
   команда пересобирает helper с новым profile. Записи доступны, как раньше.
2. **Given** `install.sh --launchd`, **Then** LaunchAgent запускает `install.sh --renew` раз в
   день и при входе в систему.
3. **Given** до конца срока меньше 2 дней или срок истёк, **When** любая команда `secret`,
   **Then** в stderr предупреждение. В нём есть команда продления.

### User Story 5 - Обратный переезд (Priority: P3)

**Acceptance Scenarios**:

1. **When** `secret migrate --back`, **Then** после Touch ID команда копирует все записи в
   файловый keychain с комментариями и сроками. Затем команда выключает новое хранилище и
   удаляет его записи.
2. **Given** в файловом keychain уже есть запись с тем же именем, **Then** команда заменяет её
   значение значением из нового хранилища.

### Edge Cases

- Helper хранилища не собран, а хранилище включено: команда выдаёт ошибку с подсказкой
  `./install.sh`.
- Profile истёк, helper не запускается: ошибка с подсказкой `./install.sh --renew`. Записи
  остаются на месте. Пересборка сохраняет access group.
- Сессия Apple ID в Xcode истекла: продление не проходит. `install.sh --renew` пишет, что нужно
  войти в Xcode → Settings → Accounts.
- Два процесса одновременно запускают процесс-агент grace: работает один, второй завершает работу.
- Процесс-агент упал: следующая команда запускает новый агент и снова спрашивает Touch ID.
- `touchid off` в новом хранилище: ошибка, защита всегда включена.
- `unlock` в новом хранилище: ничего не делает, хранилище открыто, пока открыт сеанс macOS.
- Запись в новом хранилище без `.userPresence`: её создал другой процесс. Чтение даёт ошибку
  `not protected: NAME`. Helper не отдаёт значение.
- Mac сменили или восстановили из резервной копии: записи доступны только на том Mac, где их
  создали. Резервная копия Mac их не переносит. Путь восстановления — `secret restore` из зашифрованной копии.

## Requirements *(mandatory)*

### Functional Requirements

<!-- утр-100: 1.9 — идентификаторы FR и US заданы шаблоном spec-kit -->
- **FR-001**: Helper хранилища — отдельное приложение, его собирает Xcode из исходника в репе
  и подписывает сертификат Personal Team владельца. Xcode определяет Team ID автоматически.
- **FR-002**: Запись: account `secret-cli`, service — имя, комментарий, срок `expires=`, доступ
  только на этом Mac при разблокированном сеансе, значение под `.userPresence`.
- **FR-003**: Функции helper:
  - список атрибутов без Touch ID.
  - наличие записи.
  - чтение значений с Touch ID, один вопрос на вызов.
  - запись пакетом из stdin без Touch ID.
  - изменение атрибутов с Touch ID.
  - удаление без Touch ID.
  - политика grace.
  - статус.
- **FR-004**: Значения между `bin/secret` и helper идут через stdin и stdout в hex, не через
  аргументы.
- **FR-005**: Grace держит процесс-агент helper. Он запускается при первом чтении, хранит
  подтверждённый контекст и завершается, когда grace истёк, по `secret lock` или по
  `touchid grace`. Связь с ним — сокет с доступом только для владельца.
- **FR-006**: Политика grace — запись `__secret-cli.policy` под `.userPresence`. Агент читает её
  после Touch ID. Grace больше 3600 или запись без защиты — используется 0.
- **FR-007**: Выбор хранилища: файл `~/.local/state/secret/store` со словом `dp`. Его пишет
  `migrate` и удаляет `migrate --back`. Если helper не запускается, команда выдаёт ошибку.
  Команда не переходит на файловый keychain.
- **FR-008**: `secret migrate --backup FILE` и `secret migrate --back` (User Story 1 и 5).
- **FR-009**: `install.sh` собирает helper хранилища, если есть Xcode и Personal Team. `--renew`
  пересобирает helper при сроке меньше 3 дней. `--launchd` ставит LaunchAgent.
- **FR-010**: `bin/secret` предупреждает о сроке profile меньше 2 дней. Дата берётся из файла,
  который пишет `install.sh`, без запуска helper.
- **FR-011**: Тестовая сборка: другой bundle ID и access group, Touch ID из файла, account на
  прогон, записи без `.userPresence`. Рабочая сборка не содержит этого кода.
- **FR-012**: Хук Claude Code останавливает переменные тестовой сборки и прямой вызов helper
  хранилища агентом.
- **FR-013**: Без Xcode и до `migrate` команда работает на файловом keychain, как раньше.

### Key Entities

- **Запись**: имя, значение, комментарий, срок.
- **Файл режима `~/.local/state/secret/store`**: признак того, что новое хранилище включено.
- **Политика `__secret-cli.policy`**: grace в секундах.
- **Процесс-агент**: подтверждённый контекст Touch ID, время окончания grace.

## Success Criteria *(mandatory)*

<!-- утр-100: 1.9 — идентификаторы SC заданы шаблоном spec-kit -->
- **SC-001**: Тест: после `migrate` все записи тестового хранилища имеют те же значения,
  комментарии и сроки. Ссылки `.env` работают как раньше.
- **SC-002**: Тест: все существующие проверки `tests/run.sh` проходят на файловом keychain.
  Проверки команд проходят и на тестовом новом хранилище.
- **SC-003**: Тест: в grace одна команда и две команды подряд дают один вопрос Touch ID. После
  `lock` — новый вопрос.
- **SC-004**: Ручная проверка: процесс с подписью Personal Team читает рабочее значение только
  после Touch ID. `get` спрашивает Touch ID один раз.
- **SC-005**: Ручная проверка: перенос рабочего keychain владельца, команды работают. Helper
  продлевается без участия человека.
- **SC-006**: Сборка helper хранилища без предупреждений об устаревшем API.

## Assumptions

- Personal Team выдаёт profile на 7 дней, и Xcode продлевает его без вопросов, пока Apple ID
  добавлен в Xcode (research R3).
- Атрибуты записи (имя, комментарий, срок) не защищены Touch ID, как и раньше (research R6).
- Команда удаляет и заменяет запись без Touch ID, как и раньше. Эти действия не раскрывают
  значение.
- Процесс-агент в grace отвечает любому процессу владельца, как метка grace в фиче 007.
- Файловый keychain и helper `secret-auth` остаются для режима без Xcode. Их удаление войдёт в
  другую спецификацию.
